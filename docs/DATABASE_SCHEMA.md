# Database schema (generated from the migrations)

Generated by running migrations 001-010 on PostgreSQL. All money columns end in `_paise` (integer paise; 1 rupee = 100 paise). Percentages are basis points (10000 = 100%). Every table has Row Level Security on.

## Key rules enforced by the database itself
- Only one live (draft/confirmed/completed) booking per villa; cancelled bookings stay as history.
- A confirmed booking has its own frozen payment schedule (a copy of the template). It can only change through the audited amendment function, and only for milestones that are not yet payable.
- Payments and allocations are append-only (no edits or deletes). Corrections are reversal rows. Balances are views, never stored.
- A payment must be verified by a Director before it is allocated; allocations can never exceed the payment or the milestone.
- Booking status changes only through confirm/cancel functions; the browser cannot set it directly.
- The audit log, call log, schedule history and allocations cannot be changed or deleted.
- PAN lives in its own table readable only by the Director.
- Payment requests ("demands") are carved out of one "balance asked later" line, so the schedule always totals the contract value; every request is recorded forever with what the system suggested.
- Construction updates are refused while a confirmed booking has not received the required share of the price, unless the Director released it.
